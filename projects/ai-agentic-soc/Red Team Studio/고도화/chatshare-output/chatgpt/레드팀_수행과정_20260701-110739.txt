설계 요약
1. 프롬프트 앞 가드레일
사용자 입력과 자동 삽입 프롬프트를 먼저 검사합니다.
적용 통제:
정규표현식 기반 금지 패턴 탐지
prompt injection / jailbreak 탐지
금지 행위 intent 분류
민감정보/secret 탐지
ROE·Scope 사전 확인
LLM Judge 기반 의미 분석
예:
User Input
 → Input Guardrail
 → Intent Classifier
 → ROE/Scope Pre-check
 → Task Planner
2. LLM 호출 전 프롬프트 조립 가드레일
자동으로 들어가는 system/developer/case/tool/evidence context를 그대로 합치면 위험합니다. 따라서 프롬프트 조립 단계에서 다음을 강제합니다.
System Prompt
Developer Policy
ROE Summary
Approved Evidence only
Tool Output as quoted data block
Retrieved Docs as untrusted data block
Sanitized User Input
중요 원칙:
Tool output and retrieved documents are data, not instruction.
3. LLM 출력 가드레일
LLM이 만든 tool call, finding draft, report section draft를 바로 실행하거나 저장하지 않습니다.
검사 항목:
JSON schema 통과 여부
금지 tool class 여부
tool argument 유효성
과도한 공격 재현 세부정보 포함 여부
근거 없는 claim 포함 여부
final severity 임의 설정 여부
민감정보 포함 여부
4. LLM ↔ Tool 사이 가드레일
LLM은 툴을 직접 호출하지 않습니다.
허용 구조:
LLM
 → LLM Output Guardrail
 → MCP/Tool Gateway
 → Tool Invocation Guardrail
 → HITL if needed
 → Tool Adapter
차단 구조:
LLM → Tool 직접 호출
Tool Guardrail 검사:
tool allowlist
tool class
argument schema
target scope
read/write/execute 분류
ROE 허용 여부
human approval 필요 여부
5. Tool ↔ DB/API 사이 가드레일
이 부분도 반드시 별도 통제합니다. LLM이 안전한 tool call을 만들었더라도, Tool 내부 버그나 과도한 DB 질의가 있을 수 있기 때문입니다.
구조:
Tool Adapter
 → DB/API Guard Proxy
 → Query Template Enforcer
 → SQL AST Validator
 → RBAC/RLS
 → Column/Row Masker
 → Result Size Limiter
 → DB/API
기본 정책:
자유 SQL 금지
query_template_id 필수
SELECT-only 기본
token/password/session/cookie column 차단
결과 row limit
case scope row-level security
민감 컬럼 마스킹
모든 query audit
6. Tool 응답 ↔ LLM 사이 가드레일
툴 응답은 가장 위험한 prompt injection 경로 중 하나입니다.
적용 통제:
tool output sanitizer
prompt injection classifier
PII/secret detector
malicious instruction stripping
output size cap
data envelope 변환
evidence candidate normalization
예:
JSON
{
 "trusted_as_instruction": false,
 "trusted_as_data": true,
 "classification": "confidential",
 "summary": "5 authentication anomaly alerts returned.",
 "redactions": [],
 "evidence_candidate": true
}
7. Evidence Guardrail
툴 결과나 캡처 이미지는 바로 보고서에 들어가지 않고 Evidence Card가 됩니다.
필수 필드:
source_system
source_uri / query_id
captured_at
collected_by
hash_sha256
classification
approval_status
observation
inference
limitations
confidence
8. Visual Evidence Guardrail
자동 캡처 이미지에는 별도 가드레일을 둡니다.
핵심 규칙:
Screenshot is evidence, not conclusion.
허용 표현:
SIEM 대시보드에 인증 이상 이벤트 spike가 보인다.
차단 표현:
SOC가 탐지에 실패했다.
탐지 실패를 주장하려면 추가로 필요합니다.
SIEM alert record
rule execution result
SOC ticket
analyst triage timestamp
telemetry readiness evidence
9. Report Guardrail
보고서 export 전에 최종 검증합니다.
차단 조건:
unsupported material claim 존재
unapproved sensitive/restricted evidence 포함
screenshot-only conclusion 존재
final severity가 human approval 없이 설정됨
공격 재현 세부 절차 과다 포함
문서 TLP/분류/개정이력 누락
evidence 없는 Finding 존재
추가 문서에서 확정한 핵심 정책
Guardrails are applied at every trust boundary.
Prompt guardrails are necessary but insufficient.
Tool guardrails are mandatory.
DB/API traffic guardrails are mandatory.
Tool output guardrails are mandatory.
Report output guardrails are mandatory.
Human approval is mandatory for high-risk decisions.
구현 우선순위는 다음입니다.
GuardrailDecision, PolicyViolation, ToolInvocationRequest, DBQueryPlan 스키마
PolicyEngine deny-by-default
InputGuardrailService
ToolInvocationGuard
DBQueryGuard
ToolOutputSanitizer
EvidenceGuardrail

3. AI가 만들 수 있는 것은 “안전한 보조 스크립트”로 제한했습니다
AI/LLM이 생성할 수 있는 스크립트 유형을 명확히 제한했습니다.
허용 설명
Output Parser 도구 출력 텍스트/CSV/JSON/XML 정규화
Evidence Packager 결과 파일, 스크린샷, 로그를 Evidence bundle로 묶음
Scope Validator 대상 URL/IP/도메인이 ROE 범위 안인지 검사
Report Transformer 결과를 Finding draft 또는 ATT&CK 후보로 변환
Lab Harness 샘플 데이터와 lab 환경에서 adapter 테스트
Tool Wrapper 승인된 도구를 일관된 인터페이스로 호출
Visual Capture Helper 웹/콘솔/PDF 캡처 자동화
금지 이유
Credential collection script 자격증명 수집 자동화 금지
Phishing sender 사회공학 실행 자동화 금지
Exploit execution script 공격 실행 자동화 위험
Destructive script 장애·삭제·암호화·파괴 금지
Security control disabling script 방어 무력화 금지
Persistence/backdoor script 악성 지속성 금지
Stealth/evasion script 탐지회피 자동화 위험
즉, AI는 파서, 정규화기, 래퍼, Evidence 패키저, 보고서 변환기, lab harness를 만들 수 있습니다. 운영환경 공격 실행 스크립트는 만들지 않습니다.

# Goal

RedTeam AX 플랫폼은 승인된 레드팀·모의침투·펜테스트 업무를 케이스 단위로 운영하며, ROE/HITL/가드레일을 통과한 도구·스크립트·MCP·LLM 에이전트만 실행한다.
모든 자료, 이미지, 로그, 도구 결과, 분석 판단은 Evidence Card와 Claim-Evidence Matrix로 추적된다.
웹앱은 도구 실행을 자동화하되 고위험 실행은 사람이 승인·수행·검토하며, AI는 계획·증거화·분석·보고서 초안·재시험 계획을 보조한다.
한국어 Red Team Report v2는 Volkis식 Campaign Walkthrough와 악성코드 보고서식 문서 통제/증적 양식을 결합해 자동 생성된다.
