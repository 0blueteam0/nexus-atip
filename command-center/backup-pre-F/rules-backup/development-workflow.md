# Development Workflow (RIPER+ 개발 워크플로우)

## 개요
**유연한 회귀적 개발 워크플로우** - 선형이 아닌 순환형 모델

---

## RIPER+ 워크플로우 다이어그램

```
                    ┌──────────────────────────────────────┐
                    │                                      │
                    ▼                                      │
    ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐ │
    │ SPECIFY │──▶│ EXPLORE │──▶│  PLAN   │──▶│IMPLEMENT│─┤
    │         │   │         │   │         │   │         │ │
    │ - Goal  │   │ - Code  │   │ - Arch  │   │ - Code  │ │
    │ - Scope │   │ - Pattern│  │ - Task  │   │ - Test  │ │
    │ - PRD   │   │ - Risk  │   │ - Review│   │ - Debug │ │
    └────┬────┘   └────┬────┘   └────┬────┘   └────┬────┘ │
         │             │             │             │      │
         │◀────────────┼─────────────┼─────────────┘      │
         │    Backtrack│             │                    │
         │             │◀────────────┘                    │
         │             │    Refine                        │
         ▼             ▼                                  │
    ┌─────────┐   ┌─────────┐                             │
    │ VERIFY  │──▶│ RELEASE │─────────────────────────────┘
    └─────────┘   └─────────┘      Iterate
```

---

## Phase 1: SPECIFY (명세화)

**목표**: 요구사항 명확화, PRD 작성

### 필수 산출물
| 항목 | 설명 |
|------|------|
| Goal | 달성하고자 하는 목표 |
| Scope | 범위 (포함/제외) |
| Success Criteria | 성공 기준 |
| Constraints | 제약 조건 |

### 체크리스트
- [ ] 목표가 명확한가?
- [ ] 범위가 정의되었는가?
- [ ] 성공 기준이 측정 가능한가?
- [ ] 이해관계자 확인되었는가?

---

## Phase 2: EXPLORE (탐색)

**목표**: 코드베이스 이해, 패턴 파악, 리스크 식별

### 활동
- 관련 코드 탐색 (Explore 에이전트 사용)
- 기존 패턴 분석
- 의존성 파악
- 잠재적 리스크 식별

### 체크리스트
- [ ] 관련 파일 모두 파악했는가?
- [ ] 기존 패턴 이해했는가?
- [ ] 영향 범위 분석했는가?
- [ ] 리스크 식별했는가?


---

## Phase 3: PLAN (계획)

**목표**: 구현 계획 수립, 아키텍처 설계

### 필수 산출물
| 항목 | 설명 |
|------|------|
| Architecture | 기술 아키텍처 |
| Tasks | 분해된 태스크 목록 |
| Dependencies | 의존성 그래프 |
| Timeline | 예상 일정 (선택) |

### Human Review 필수
- 계획 승인 없이 구현 진행 금지
- Plan Mode 사용 권장
- 3가지 이상 선택지 제시

### 체크리스트
- [ ] 아키텍처 설계 완료?
- [ ] 태스크 분해 완료?
- [ ] 사용자 승인 획득?

---

## Phase 4: IMPLEMENT (구현)

**목표**: 코드 작성, 테스트 실행

### 원칙
- 승인된 계획만 구현
- 점진적 구현 (작은 단위)
- 테스트 우선 (TDD 권장)
- 문서화 병행


### 체크리스트
- [ ] 계획대로 구현했는가?
- [ ] 테스트 통과했는가?
- [ ] 코드 품질 확인했는가?

---

## Phase 5: VERIFY (검증)

**목표**: QA, 리뷰, 품질 검증

### 검증 항목
| 항목 | 도구 |
|------|------|
| Unit Test | pytest, jest |
| Integration Test | CI/CD |
| Security Scan | 보안 도구 |
| Code Review | PR Review |

### 체크리스트
- [ ] 모든 테스트 통과?
- [ ] 보안 취약점 없음?
- [ ] 리뷰 승인 획득?

---

## Phase 6: RELEASE (릴리스)

**목표**: PR 생성, 배포, 모니터링

### 산출물
- Pull Request
- CHANGELOG 업데이트
- 배포 (선택)


---

## Phase Gate System (품질 관문)

각 단계 전환 시 **Gate Check** 수행:

| Gate | 검증 항목 | 통과 기준 | 회귀 조건 |
|------|----------|----------|----------|
| **G1** | PRD 완성도 | Goal/Scope/Criteria 명확 | 요구사항 불명확 |
| **G2** | 컨텍스트 충분 | 관련 코드/패턴 파악 | 탐색 부족 |
| **G3** | 계획 승인 | Human Review 완료 | 아키텍처 변경 필요 |
| **G4** | 코드 완성 | 테스트 통과 | 버그/에러 발생 |
| **G5** | QA 통과 | 품질 기준 충족 | 리뷰 반려 |

---

## 회귀 (Backtrack) 규칙

### 허용되는 회귀
- Implement → Explore: 추가 컨텍스트 필요 시
- Implement → Plan: 계획 수정 필요 시
- Plan → Explore: 탐색 부족 발견 시
- Verify → Implement: 버그 수정 필요 시

### 회귀 시 필수 행동
1. 회귀 이유 명시
2. 이전 산출물 보존
3. 변경 사항 문서화

## 복잡도 기반 워크플로우 선택

| 복잡도 | 기준 | 워크플로우 |
|--------|------|-----------|
| **Trivial** | 단일 파일, <30분 | Direct Implement |
| **Simple** | 2-3 파일, 30분-2시간 | Light Plan → Implement |
| **Medium** | 4-10 파일, 2-8시간 | Full RIPER+ |
| **Complex** | 10+ 파일, 1-3일 | Full RIPER+ + Review |
| **Critical** | 아키텍처 변경 | Architect Review + Full RIPER+ |

### 자동 복잡도 판단
```
[Task Input]
     │
     ▼
┌──────────────┐
│ 파일 수      │
│ 변경 범위    │
│ 의존성       │
└──────┬───────┘
       │
   ┌───┴───┐
   ▼       ▼
[Simple] [Complex]
```

## Reflection Pattern (자기 검증)

모든 구현 후 자기 검증 수행:

```
1. Error Check: 에러 없는가?
2. Gap Check: 요구사항 누락 없는가?
3. Quality Check: 품질 기준 충족하는가?
```

Score 미달 시 자동 Refine & Retry
