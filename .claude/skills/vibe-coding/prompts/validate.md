# 검증 프롬프트 템플릿

## 목적
AI 생성 코드의 품질과 보안 검증

---

## 자동 검증 요청

### 보안 검토
```
방금 생성한 코드를 보안 관점에서 검토해줘:

1. 하드코딩된 시크릿이 있어?
2. SQL 인젝션 가능성은?
3. XSS 취약점은?
4. 인증/인가 문제는?
5. 민감 데이터 노출 위험은?

문제가 있으면 수정된 버전도 제공해줘.
```

### 성능 검토
```
이 코드의 성능 문제를 분석해줘:

1. 시간 복잡도는? (Big O)
2. 불필요한 반복이 있어?
3. 메모리 누수 가능성은?
4. N+1 쿼리 문제는?
5. 최적화 가능한 부분은?
```

### 로직 검토
```
이 코드의 엣지 케이스를 확인해줘:

1. 빈 입력값 처리
2. null/undefined 처리
3. 경계값 (0, 음수, 최대값)
4. 동시성 문제
5. 에러 상황 핸들링
```

## 수동 검증 체크리스트

### 코드 품질
- [ ] 변수/함수명이 명확한가?
- [ ] 중복 코드가 있는가?
- [ ] 매직 넘버가 있는가?
- [ ] 주석이 필요한 복잡한 로직이 있는가?

### 보안
- [ ] `console.log`에 민감 정보가 있는가?
- [ ] 환경 변수로 분리할 값이 있는가?
- [ ] 입력 검증이 되어 있는가?
- [ ] CORS 설정이 적절한가?

### 의존성
- [ ] 불필요한 의존성이 있는가?
- [ ] 라이선스가 호환되는가?
- [ ] 알려진 취약점이 있는가? (`npm audit`)

### 테스트
- [ ] 단위 테스트가 있는가?
- [ ] 핵심 경로가 테스트되었는가?
- [ ] 엣지 케이스가 테스트되었는가?

## 검증 도구 명령어

```bash
# JavaScript/TypeScript
npm audit                    # 보안 취약점
npm run lint                 # 코드 스타일
npm test                     # 테스트 실행
npx tsc --noEmit             # 타입 체크

# Python
pip-audit                    # 보안 취약점
ruff check .                 # 린트
pytest                       # 테스트 실행
mypy .                       # 타입 체크

# 공통
git diff                     # 변경사항 확인
```

## AI 맹신 방지 원칙

### 항상 의심할 것
1. **"이 방법이 최선이야"** → 대안 질문하기
2. **복잡한 정규식** → 테스트 케이스로 확인
3. **외부 API 호출** → 실제 응답 구조 확인
4. **날짜/시간 처리** → 타임존 확인
5. **암호화/해싱** → 표준 라이브러리 사용 확인

### 검증 질문
```
"이 접근법의 단점은 뭐야?"
"다른 방법과 비교하면?"
"프로덕션에서 문제될 수 있는 부분은?"
```
