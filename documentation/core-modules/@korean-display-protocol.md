# 한국어 표시 프로토콜 (Korean Display Protocol) 
## [KR] 최상위 우선순위 지침 - ULTRA CRITICAL

### [!] 핵심 원칙
**모든 작업 과정을 한국어로 병기하여 사용자 이해도 극대화**

### [*] 적용 범위
- 도구 호출 전후 설명
- 작업 진행 상황 표시
- 에러 메시지 해석
- 결과 요약 및 분석

## [>>] 표준 한국어 표시 형식

### 1. 도구 호출 전 (Pre-Tool Korean Annotation)
```
[작업] {무엇을} {어떻게}
[목적] {왜 하는지}
[예상] {기대 결과}
```

### 2. 도구 실행 중 (During-Tool Status)
```
[진행] {현재 단계} ({진행률}%)
[상태] {작업 상황}
```

### 3. 도구 실행 후 (Post-Tool Summary)
```
[완료] {결과 요약}
[영향] {변경 사항}
[다음] {후속 작업}
```

### 4. 에러 발생 시 (Error Handling)
```
[문제] {무엇이 잘못됨}
[원인] {왜 발생했는지}
[해결] {어떻게 고칠지}
```

## [*] 실제 적용 예시

### 파일 작업 예시
```
[작업] index.html 파일 읽기
[목적] 현재 구조 파악 및 수정 지점 확인

{도구 실행}

[완료] 2500줄 파일 읽기 성공
[발견] 뉴스 모듈이 325행에 위치
[다음] 모듈 업데이트 진행
```

### 복잡한 워크플로우 예시
```
[워크플로우] 뉴스 아카이빙 시작
├─ [1단계] 웹 검색 (5개 소스)
├─ [2단계] 콘텐츠 추출 (AI 요약)
├─ [3단계] 데이터베이스 저장
└─ [4단계] UI 업데이트

[진행] 1단계 완료 - 15개 기사 발견
[진행] 2단계 진행중 - 요약 생성 (60%)
```

## [!] 자동 적용 규칙

### 트리거 조건
1. **도구 호출 시** → 자동으로 한국어 설명 추가
2. **3줄 이상 영어 출력** → 한국어 요약 제공
3. **에러 메시지** → 즉시 한국어 해석
4. **복잡한 로직** → 단계별 한국어 가이드

### 간결성 유지
- 한국어 설명은 **1-2줄**로 제한
- 중복 설명 금지
- 핵심만 전달

### ASCII 아트 활용
```
[작업 흐름]
시작 ─→ 분석 ─→ 실행 ─→ 검증 ─→ 완료
  ↓                          ↑
  └──── 에러 발생 시 롤백 ───┘
```
